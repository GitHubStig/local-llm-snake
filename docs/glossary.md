# Glossary

Terms used across the [ADRs](adr/) and the code. Where a word is overloaded in
the wider ecosystem, the entry says which meaning applies here.

### Tick

One advance of the game clock. Under ADR-0001 ticks fire on a timer regardless
of whether a controller has answered. Tick length is the speed setting: slow
1000ms, normal 400ms, fast 150ms, turbo 60ms.

### Deadline

The point within a tick after which no answer will be used. Missing it means
the snake **continues straight**.

### Controller

Anything that answers "which way do I turn?" — `human` or `ai`. One interface,
always asynchronous (ADR-0006). Human is a controller whose promise resolves on
the next keypress.

### Takeover

Switching the active controller to `human` mid-run. Not a special mechanism: it
is a controller swap.

### Shadow mode

An optional toggle that keeps querying the AI while the human drives, so the
panel can show what it *would* have chosen. Off by default.

### Overlap

Keeping one request continuously in flight rather than one per tick, so a
controller slower than the tick still contributes moves. Each tick consumes the
freshest stored answer.

### Staleness

How many ticks old the board was when the current stored answer was computed.
Displayed; capped; an answer past the cap is discarded.

### Legal move

One of the at-most-three non-reverse directions. A **rules fact**, not a hint:
reversing is fatal in every configuration because the neck does not move away
(ADR-0003). Used for the schema enum, for re-validating stale answers, for the
illegal-on-arrival counter, and for filtering human input — not for the prompt
prose.

### Assistance level

How much precomputed analysis the prompt hands the model, 0 to 4 (ADR-0008).
Default 0. The primary experimental variable.

### Representation

How the board is described to the model: grid, coordinates, or both. Default
both.

### Thinking

Chain-of-thought generated by the model *before* its answer, controlled by
Ollama's `think` parameter and returned in `message.thinking`. **Always off
here.** Distinct from `why` below.

### `why`

A short justification string in *our* output schema, written as part of the
structured answer. Toggleable, default on, capped by `num_predict`. Named `why`
rather than `reasoning` specifically to avoid confusion with thinking.

### Hunger

Ticks since the last food. Exceeding `100 + length * 10` kills the snake, which
removes the degenerate strategy of circling safely forever (ADR-0003).

### Terminal states

**Crashed** (wall or self), **starved** (hunger), **won** (snake fills the
board). Recorded distinctly so failure modes do not blur together.

### Model share

The proportion of moves the model actually decided, as opposed to moves that
fell through to continue-straight. A direct measure of whether a model can keep
up with the tick.

### Typed failures

Why a model did not decide a move: **timed out**, **arrived stale**, **illegal
on arrival**, **game-invalid** (schema-valid, in-enum, and still suicidal).

### Prefix caching

Reuse of cached computation when consecutive prompts share a leading token
sequence. A **strict match from token 0** — anything varying at the head
destroys it. Measured at 8,763ms to 112ms on a 7,243-token prefix (ADR-0008).

### Run record

In-memory log of a single game: seed, ruleset, switch settings, and per tick
the direction, who decided it, and the latency.

### Provider

A backend that can answer a completion request — Ollama, `fm serve`, later JEV.
Sits beneath the `ai` controller; adding one is not a new controller
(ADR-0007).

### Tier

An advisory label on a discovered model — unusable, avoid, slow — derived from
API metadata and replaced by measured latency once the model has run. Labels
never block selection.
